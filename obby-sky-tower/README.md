# Sky Tower Obby

A 1,000-stage, procedurally generated tower obby for Roblox (ten towers of 100 stages joined by
portals), built entirely in code as a
[Rojo](https://rojo.space) project. See `DESIGN.md` for the game loop, obstacle library,
economy and the list of Creator Dashboard items.

`SkyTowerObby.rbxlx` is a ready-built place file. The towers are **generated by the server**
(tower 1 at start-up, the others when somebody gets near them), so in Edit mode you only see the
scripts. Press **Play** to see the world.

## Open in Studio

**Option A — place file (no tools needed)**
1. Double-click `SkyTowerObby.rbxlx` (or File → Open in Studio).
2. Home → **Play**. You spawn in the lobby; walk forward under the START arch.

**Option B — live sync with Rojo (for editing code)**
1. Install the Rojo plugin in Studio (Plugins → Manage Plugins, or `rojo plugin install`).
2. From this folder run: `../huerta-tycoon/tools/rojo.exe serve default.project.json`
3. Open a new Baseplate in Studio, delete the Baseplate part, Rojo plugin → **Connect**.

To preview a tower in Edit mode (without Play), paste this in the Command Bar:
`local G = require(game.ServerScriptService.Server.StageGenerator) G.buildLobby() G.buildTower(1)`
(delete the created `Towers`, `Lobby` and `Decor` folders before publishing — the server builds
them itself).

## Test in Studio

- Game Settings → Security → **Enable Studio Access to API Services** (for saving + the leaderboard).
- With product IDs at 0, Studio shows a working **SKIP STAGE (Studio test)** button that skips for
  free (it does not exist in a published build). Passes are NOT treated as owned
  (`Config.StudioOwnsPasses = false`), so the jump you test is the jump players get; set it to
  true to try coils / VIP / 2x coins.
- Useful checks: skip to 9 → reach stage 10 (world banner + first shop deck), skip to 100 (summit:
  gift, lounge, portal, win panel), take the portal to tower 2, Rewards → codes `RELEASE`,
  `SKYHIGH`, `CLOUDS`.
- Test → Device emulator: try a phone in landscape to check the UI scale.

## Publish

1. File → **Publish to Roblox As…** → create a new experience.
2. Game Settings → Security → enable **API Services** (DataStores).
3. On the Creator Dashboard create the passes, products and badges listed in `DESIGN.md`,
   paste the IDs into `src/shared/Config.luau`, rebuild (below) or sync, and publish again.
4. Set `Config.StudioFreeSkips` as you like (it only ever works inside Studio).
5. Change or add codes in `Config.Codes`. Bump `Config.DataStoreName` only if you want a data wipe.
6. Experience settings: set genre to Obby/Platformer, max players ~20-30, add an icon and thumbnails
   (screenshots from Studio) and a description.

## Build and verify from the command line

```sh
cd C:/work/_Personal/proyectos/obby-sky-tower
../huerta-tycoon/tools/rojo.exe sourcemap default.project.json -o sourcemap.json
../huerta-tycoon/tools/luau-lsp.exe analyze --definitions=../huerta-tycoon/tools/globalTypes.d.luau --sourcemap=sourcemap.json src
../huerta-tycoon/tools/luau.exe tests/layout_test.luau
../huerta-tycoon/tools/luau.exe tests/rules_test.luau
../huerta-tycoon/tools/luau.exe tests/locale_test.luau
../huerta-tycoon/tools/luau.exe tests/p0_test.luau
../huerta-tycoon/tools/luau.exe tests/visual_test.luau
../huerta-tycoon/tools/rojo.exe build default.project.json -o SkyTowerObby.rbxlx
```

Studio playtest (opens Studio on the second monitor, prints `[TEST]` lines, about 6 minutes):
`powershell -ExecutionPolicy Bypass -File ../huerta-tycoon/tools/studio_run.ps1 -ProjectDir <this folder> -Project test.project.json -TimeoutSec 1000`.
The runner prints only the first 200 lines; the full result is in the newest Studio log
(`%LOCALAPPDATA%/Roblox/logs`, lines with `[TEST`). The playtest also prints `[TEST] PERF` lines
(parts, emitters, lights, memory, server Heartbeat, client fps / render time / draw calls,
network, remote traffic) and fails if a budget is exceeded.

Screenshot tours for the same runner (`-Sizes ...`, one view per window size):
`shots.project.json` (38 views: lobby, a wide and a player-height view of every world of tower 1,
obstacle close-ups, a shop deck, the summit with gift and portal, the lounge, the base island of
tower 2, towers 2 / 5 / 10, a checkpoint being reached), `shotslow.project.json` (the same tour as
a player on minimum graphics sees it), `uishots.project.json` (HUD, open menu, every panel, the
skip offer; 9 steps per resolution + UI audit) and `i18nshots.project.json` (one language per
screenshot).

`tests/visual_test.luau` checks the visual layer's pure logic: one sane lighting profile per world
and a sky that blends continuously with height, every scenery piece clear of the lane and inside
its world's height band (for 26 seeds), and the progress-bar gradient keypoints.

`tests/layout_test.luau` checks every hop of the 1,000 stages against the real jump physics
(JumpPower 50, WalkSpeed 16): the share of the physical reach each hop uses never exceeds 93%
and no hop climbs more than 4.4 studs; the difficulty curve really rises; lasers leave time to
pass and wind can be steered against; lanes stay clear of the core; shop decks never touch the
route; save pads get scarcer; the same seed gives the same map (25 other seeds are valid too).

`tests/rules_test.luau` checks the pure game rules: which pad you respawn on, skips, portals,
which towers must exist, gifts, shop purchases and their expiry, lounge rules, what makes a run
unranked, and that the "(Studio test)" skip button cannot appear in a published build.

## Changing the map

`Config.MapSeed` picks the towers; any seed works (the test checks 25 extra seeds). Difficulty,
gaps, rises and the unlock order of obstacle kinds are all in `src/shared/Layout.luau`.
Run the test after any change there.
